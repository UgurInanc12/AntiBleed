## Deliberate boundaries and remaining risks

1. Non-waiting ring access rejects writes or emits silence if a copy is already in progress.
   This removes data races, but is not a proof of inaudible contention. Measure dropout counters,
   callback timing and end-to-end latency on the real Mac before release.
2. No fresh macOS compile or loaded-driver test was possible on this Windows host.
   The historical macOS CI success does not cover this diff.
3. HAL sample clocks, prolonged capture/writer drift, sleep/wake, daemon restart and multiple
   recording clients still need hardware verification. No claim of complete driver certification.
4. NSAppleScript stays on the main thread as required. Whether the authorization modal blocks
   other UI work must be tested on Mac. No unsupported background NSAppleScript workaround added.
5. Privacy_AudioCapture deep-link behavior is not verified. The review's assertion that it never
   exists was unsupported by its generic Apple support citation, so it was not changed speculatively.
6. The review claimed LinkerSetting.unsafeFlags cannot propagate and quoted a sentence absent from
   its cited Swift documentation. No duplicate flags added without an actual linker failure.
7. NSTemporaryDirectory is user-specific, not /tmp. That does not establish a root-access failure.
   The suggested fixed world-writable /tmp name was rejected; unique staging is used instead.
8. Manual Scripts/install-driver.sh remains a legacy developer fallback, not the tested app
   transaction. Prefer the in-app flow. Developer ID signing/notarization is not certified here.
9. System-audio permission denial does not yet have an independently verified raw-mic fallback.
   Do not advertise this as working from the existing checklist alone.
